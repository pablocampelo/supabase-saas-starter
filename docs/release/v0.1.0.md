# Supabase SaaS Starter v0.1.0

**First Scope 2.0 repository release.** Supabase SaaS Starter is a **cloneable SaaS foundation**, not a managed hosted service.

## Included

- Next.js App Router, strict TypeScript, Tailwind, one semantic UI theme and buyer-editable product configuration.
- Supabase Auth with Google OAuth and verified email/password, confirmation/resend, recovery/reset, protected sessions and an Account surface.
- Versioned Supabase Postgres migrations, generated DB types, owner-scoped RLS and the removable Example Resource.
- Stripe test/live-isolated Pro monthly/annual Checkout, Customer Portal, signed and idempotent webhooks, paid-through entitlement, concurrency safeguards and operator reconciliation.
- Public landing/pricing/Help/legal templates, private Dashboard/Billing/Account/Example, SEO and responsive/accessibility checks.
- Pinned dependencies and a CI workflow for frozen installation, lint, typecheck, tests, production build, real Postgres authorization and browser E2E.

## Verification

The release is accepted only after the **exact tagged commit** passes GitHub Actions CI.

Hosted, disposable release-candidate evidence exercised Supabase SMTP email verification, password recovery and login, Google OAuth into an authenticated Dashboard, a paid **Stripe test-mode** monthly Checkout, the signed remote webhook, and Pro access from a confirmed paid-through invoice. Separate Stripe test fixtures and regression tests covered annual billing, payment/cancellation/renewal semantics, concurrency, signature rejection and reconciliation.

The **replaceability exercise** rebranded the starter and replaced Example with a Projects domain (including a new field and migration), preserving Auth, Billing, RLS and entitlement while passing database and application checks. The exercise was not merged: Example remains the buyer-facing starter domain.

## What the buyer must configure

Each deployment owns its Supabase project, Google OAuth, verified Resend SMTP sender/templates, Stripe products/Prices and webhook signing secret, support contact, legal policies, migrations, DNS and **Vercel** environment. A clean clone intentionally includes **no hosted QA credentials, billing data or dependencies on the seller's RC**.

Follow [Setup](../SETUP.md) and [Architecture](../ARCHITECTURE.md); consult the [Billing runbook](../runbooks/BILLING.md) for operational drift. The [canonical Scope](../product/SCOPE.md) lists the supported contract and deliberate exclusions.

**Distribution:** use the Git commit/tag as the authoritative version. A ZIP is only a derived copy.
